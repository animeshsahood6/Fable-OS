# ADR-010 — The kernel routes through the gateway; the successor kernel runs weekly parity
**2026-07-10 · Accepted** — ratifies [ARCHITECTURE-V2](../ARCHITECTURE-V2.md) §5/§12; revokes the kernel provider exception in ADR-002.

**Context.** ADR-002 granted the agent kernel an exception to use its provider natively. The red-team review ([C4](../reviews/2026-07-09-red-team-review.md)) showed this made provider-agnosticism a façade: the kernel *is* the system — it thinks, plans, codes, and acts — so losing its provider does not "degrade quality" as Law 6 promises, it removes L4 entirely. The designated successor (ADR-003) was "installed once, smoke-tested, left dormant" — a contingency nobody rehearses is a contingency that fails. The June 2026 Fable 5 export-control suspension demonstrated that a frontier model can become unavailable overnight for entirely non-technical reasons.

**Decision.**

1. ADR-002's kernel exception is **revoked**. The kernel's reasoning model is routed through the gateway (`localhost:4000/v1`) like every other consumer, so the brain can be repointed to an alternate or local model by editing `config\models.yaml`.
2. Where the incumbent kernel cannot technically route its own model through the gateway (a harness limitation, not a policy choice), that deviation is recorded in COMPONENTS.md as a known containment gap, and item 3 becomes the load-bearing control.
3. The **successor kernel runs a real weekly parity job**: the same task file executed through the primary and successor kernels, outcomes diffed into `journal\weekly-status.md`. Provider-agnosticism is thereby *continuously exercised* — the only kind that survives contact with a dead provider.

**Consequences.** If the primary provider vanishes on a Tuesday, Monday's parity run proves the successor works. Cost: a weekly job's tokens and a second kernel kept installed and current. The parity diff doubles as the enforcement mechanism for ADR-021 (kernel-sugar containment): the week a convenience becomes a dependency, parity fails loudly.

**Alternatives considered.** (1) *Dormant successor, quarterly smoke-test* (V1) — rejected: unrehearsed recovery is fiction; this is the exact flaw C4 named. (2) *Active-active dual kernels* — rejected: doubles operating complexity for a single-operator system (Law 10) without adding survivability beyond weekly parity. (3) *Keeping the ADR-002 exception with a stronger successor plan* — rejected: leaves the founding requirement ("everything provider-agnostic") unmet at the system's center.

**Future review criteria.** Reopen if: (a) parity fails two consecutive weeks — incident, root-cause, and either fix containment or re-designate the successor; (b) the successor kernel's project dies (COMPONENTS.md names the next candidate; currently Goose, with OpenHands as alternate — see the [2026-07-10 review](../reviews/2026-07-10-architecture-review.md) §3.1 A6); (c) the incumbent kernel gains native gateway routing — remove the documented deviation of item 2.

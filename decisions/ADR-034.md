# ADR-034 — Voice-first surface: speech sanitization seam, native barge-in, and the voice-state file contract
**2026-07-13 · Accepted** — operator directive 2026-07-13 (voice live results: heard PASS, replied PASS, **barge-in FAIL**, ambient untested; plus "TTS speaks Markdown" and "overlay follows voice" orders). Implementation decisions inside ADR-022/031's frozen shapes; no frozen document touched.

**Context.** Three defects/orders from live operation: (1) barge-in never fired; (2) Kokoro literally speaks Markdown ("asterisk asterisk…") and roleplay notation; (3) the overlay is a separate client — the operator wants it to follow the voice conversation (fade in on wake, listening/thinking indicators, reply text, fade out on idle), with the browser demoted to fallback.

Root cause of (1), from the code: in wake-word mode RealtimeSTT starts a recording **only after a wake-word detection**, and `on_recording_start` was the sole interrupt trigger — so while TTS plays, nothing is armed to interrupt. The pinned RealtimeSTT 1.0.2 natively provides both missing pieces: `on_wakeword_detected` (fires during playback too) and `wake_word_activation_delay` (a VAD-active window after each monitoring start in which speech needs **no** wake word — which is also exactly the "conversation continues until idle timeout" behavior ADR-022's `idle_timeout_s` knob declared but never implemented, and the ambient flow the overlay integration needs).

**Decision.**

1. **Speech sanitization is a permanent seam in the voice adapter** — `config\kernel\jarvis_speech.py` (Law 3 glue, own file, pure stdlib): a deterministic cleaner that strips/converts Markdown (bold/italic/underline, fences → "Code omitted", inline code, headings, links, tables, bullets, blockquotes), roleplay/stage directions (laugh-family → "Haha.", other short actions dropped), hidden-reasoning tags (`<think>`-family, held and discarded even when split across stream deltas), and residual formatting symbols — **before any text reaches Kokoro**. UI surfaces keep raw Markdown untouched.
2. **The Kernel Constitution and personas are deliberately NOT modified.** The interface drops client system turns by design (Convention 5 keeps one persona source), the model cannot know its destination, and a prompt is a probabilistic fix for a deterministic requirement. The seam that knows the destination (the voice adapter) does the cleaning — producer ≠ verifier applied to formatting. If a voice-aware persona is ever wanted, that is an interface/router change under its own decision.
3. **Barge-in uses the component's native hooks, no new parts:** `on_wakeword_detected` → interrupt TTS instantly ("hey jarvis" always cuts JARVIS off); `wake_word_activation_delay = idle_timeout_s` → after wake, conversation continues wake-free (VAD), so `on_recording_start` fires on any speech — including over TTS, giving natural mid-conversation barge-in; after `idle_timeout_s` of silence the wake word re-arms (passive). A second energy-monitoring mic stream was considered and **rejected** (device contention on the BT/Iriun mic; Law 10).
4. **The voice-state file contract** (ADR-008: files are the coordination substrate; no sockets between adapters): the voice adapter writes `data\voice-state.json` — `{ts, state: passive|listening|thinking|speaking, you, reply}` — on transitions, overwritten in place (single current state, no history; ADR-032 retention rule; gitignored, T2, Brain-only). Any surface may read it; none may write it but voice.
5. **Overlay voice-follow:** `config\kernel\jarvis_voicewatch.py` (own Law 3 file, consumed by the overlay when `voice_follow.enabled`): polls the state file (~300 ms, only while the overlay process runs — no new process), fades the glass in on listening, shows listening/thinking indicators, renders the operator's words and the streaming reply, and fades out after a grace period in passive. Manual summon/dismiss and typed chat (`/look` included) keep working; Open WebUI remains the untouched fallback surface.

**Consequences.** Barge-in and ambient continuation come from configuration of an already-adopted component, so rollback is a config/callback revert. Speech can never regress into Markdown regardless of model churn (the guarantee is code, not prompt). The overlay becomes JARVIS's face with zero new processes and zero new trust surface (state file is T2 data flowing operator-ward). Cost: one more glue file each side of the contract; the state file is polled (bounded, in-process, ~3 reads/s while the overlay runs).

**Alternatives considered.** (1) *Prompt-only fix for Markdown* — rejected (probabilistic; and the interface strips client system turns by design); (2) *sanitizing inside the interface for everyone* — rejected: the browser UI legitimately renders Markdown; destination-specific cleaning belongs at the destination seam; (3) *WebSocket/pipe between voice and overlay* — rejected: ADR-008/029 (no bus, no inter-adapter sockets; files are the substrate); (4) *second input stream for energy barge-in* — rejected above.

**Future review criteria.** Reopen if: (a) RealtimeSTT's successor loses `on_wakeword_detected`/`wake_word_activation_delay` — the barge-in contract must be re-satisfied before any swap (Law 4 gate); (b) a second surface starts consuming `voice-state.json` — version the schema (`v` field) at that moment; (c) sanitizer rules grow past Law 3's budget — adopt a component (e.g. a Markdown parser) instead of growing regexes; (d) polling is ever replaced — only by an OS file-watch primitive (host-adapter role), never by a bus.

# ADR-028 — ADR-014 execution timing revised: Windows 11 becomes a scheduled infrastructure upgrade with a hard ceiling
**2026-07-11 · Accepted** — supersedes the *timing* of ADR-014 (the Phase 0 exit gate); ADR-014's substance (Windows 11 + uv substrate) stands unchanged.

**Context.** ADR-014 made Windows 11 migration a Phase 0 exit gate. The operator has re-weighed the trade under two constraints the original decision did not carry: a July 12 working-system milestone, and a solo non-programmer operator for whom a working JarvisOS on Windows 10 is worth more than a delayed one on a perfect substrate. The T6a posture audit (2026-07-11) materially changed the risk picture the gate was built on: the machine is **receiving security updates through June 2026** (ESU-class updates active, e.g. KB5094127 2026-06-10), Defender and the firewall are healthy, browsers are current, and by architecture the Brain has **zero public exposure** (ADR-026: tailnet only, no port forwarding). The substrate is EOL-by-label but patched-in-fact.

**Decision.**

1. Windows 11 migration is removed from the Phase 0 exit gate and becomes a **scheduled infrastructure task** with a hard ceiling: **complete before 2026-10-01, or before any Phase 6 outward-facing capability ships — whichever comes first.** (Consumer ESU coverage ends 2026-10-13; the ceiling leaves margin.)
2. Windows 10 (build 19045, ESU-patched) is the **supported implementation platform** for Phases 1–5 in the interim.
3. Compensating controls, verified and standing: ESU-class patching (checked at every quarterly checkup — if updates stop arriving, the ceiling collapses to "migrate now"), firewall + Defender healthy, tailnet-only exposure, and no outward-facing capabilities before migration.
4. ADR-020's ACTOR sandbox uses its stated Windows 10 baseline (dedicated non-admin account); Agent Workspace remains the optional enhancement collected at migration.
5. The validation suite's Windows 11 check reports **PENDING (accepted under ADR-028)** — kept visible on purpose; an accepted debt that disappears from view stops being a debt and becomes a surprise.
6. The migration itself follows the checklist recorded in the 2026-07-11 revised-T6 plan (backup → in-place upgrade → D:-letter check → toolchain check → `tests\phase-0.ps1 -RequireWindows11` green → registries updated).

**Consequences.** Phase 0 closes on 2026-07-11 and Phase 1 can deliver a working system by the milestone. The cost is honest: Phases 1–5 run on an OS whose patch lifeline ends 2026-10-13, bounded by the ceiling date, the quarterly patch-pulse check, and the architecture's no-public-exposure posture. The eligibility work is already banked (T1: TPM 2.0, Secure Boot, supported CPU — all verified), so the migration is an operational afternoon, not a project.

**Alternatives considered.** (1) *Keep the gate, upgrade tonight* — rejected by the operator's stated value ranking; the July 12 milestone wins while the risk is compensated. (2) *Drop ADR-014 entirely* — rejected: the destination is unchanged and the reasons (EOL substrate, native MCP, Agent Workspace) all still hold; only the sequencing changed. (3) *Defer with no ceiling* — rejected: an undated deferral is how C1 happened the first time; the ceiling and the quarterly pulse are the difference between a decision and a drift.

**Future review criteria.** Reopen (in the direction of *migrate immediately*) if: (a) ESU-class updates stop arriving (quarterly check or watchdog notices no security update in >45 days); (b) a critical unpatched Windows 10 vulnerability is exploited in the wild with no ESU fix; (c) any Phase 6 work is proposed before migration — the ceiling clause fires; (d) 2026-10-01 arrives — no further deferral may be recorded without a superseding ADR that names the new compensating control for a genuinely unpatched OS, and the bar for that is deliberately set high.

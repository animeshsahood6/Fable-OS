# ADR-021 — Kernel-native memory is a cache: canonical memory lives only in D:\Fable OS
**2026-07-10 · Accepted** — from the [2026-07-10 architecture review](../reviews/2026-07-10-architecture-review.md) §3.1 A5 / §5.4 / §6 R3; extends ADR-003's containment rule.

**Context.** ADR-003 contained the kernel by forbidding it exclusive state, and the red-team (I10) warned that kernel idioms were already leaking into "kernel-neutral" contracts. The gravity well has since deepened: Claude Code shipped native Auto Memory (February 2026) — per-project Markdown directories with a MEMORY.md index the agent maintains *by itself*, outside `D:\Fable OS\`, in a kernel-owned location. It is the same shape as this system's `memory\` design (a vindication), and precisely the mechanism by which the canonical store forks silently (a threat): every session the kernel writes memory to its own directory is a session that violates Law 5 without anyone typing a wrong command. Consumer-side, provider memory features are silos — portability between them is a battleground, not a given.

**Decision.**

1. **Canonical memory lives only in `D:\Fable OS\memory\`** (plus quarantine per ADR-013) and `journal\`. Nothing the system must remember may exist solely in a kernel-native memory store, a provider-side memory feature, or any model's weights.
2. **Kernel-native memory is configured as a view of the canonical store** — pointed into `D:\Fable OS\memory\` where the kernel allows it, or mirrored into the canonical store in the same session where it does not (the same-day rule of MAINTENANCE.md §5, now with a specific target).
3. **Provider-side memory features (ChatGPT/Gemini/Claude consumer memory) are treated as caches of convenience** — never written to as a system act, never relied on, never migrated *from* (anything worth keeping enters `memory\` through the normal write discipline, including quarantine for T2/T3-derived content).
4. **The weekly successor-parity job (ADR-010) is this rule's test**: the successor kernel runs with *no* access to the incumbent's native memory. If parity degrades because knowledge lived only in kernel memory, containment failed and the gap is closed that week.

**Consequences.** The kernel's best new convenience works *for* the canonical store instead of quietly replacing it; model and kernel replacement remain amnesia-free (`SUCCESSION_ENGINE` §4.2). Cost: some kernel memory ergonomics are constrained by pointing them at our tree, and the mirror rule adds a small session-end discipline where pointing is impossible.

**Alternatives considered.** (1) *Let the kernel own working memory, sync periodically* — rejected: periodic sync means a window where the only copy of something lives in the mortal component; "periodically" is how the same-day rule dies. (2) *Forbid kernel memory features entirely* — rejected: forfeits real capability the kernel gives for free, and unenforceable against a feature designed to be automatic; redirection beats prohibition. (3) *Adopt the kernel's memory directory as the canonical location* — rejected: relocates the system's soul into the one component designed to be replaceable (inverts ADR-003).

**Future review criteria.** Reopen if: (a) the parity job reveals kernel-memory dependence — close the gap, and if it recurs, tighten to per-session automated mirroring; (b) the kernel removes the ability to point its memory at an external directory — the mirror path becomes mandatory and this ADR's cost rises; reassess; (c) a genuine open standard for portable agent memory emerges — re-evaluate whether canonical memory can speak it natively.

# ADR-023 — Completing the skills library: S-013…S-115 are authored as post-freeze artifacts at the frozen index's paths
**2026-07-10 · Accepted** — from the [2026-07-10 architecture review](../reviews/2026-07-10-architecture-review.md) §4.1; operates under ADR-016 item 4.

**Context.** The frozen `skills\README.md` indexes **115 skills across 13 category files**; only file 01 (S-001…S-012, Thinking & Planning) exists. The remaining 103 skills — including the ones Phase 2 depends on most (kernel instructions, job authoring, injection hardening, memory write discipline) — are cited by S-### ID across the corpus and dangle. The extraction phase is closed by operator directive, so these can never be "extracted from the founding architect"; yet the IDs are load-bearing references and the index is frozen. The red-team's Missing Skills list (§8) independently names several of the same gaps.

**Decision.**

1. The missing skill files (`02-architecture.md` … `13-meta.md`) are **authored as new implementation artifacts at exactly the paths and ID ranges the frozen index declares**, so every existing S-### citation resolves. Creating files the frozen index already names fulfills the index; it edits nothing.
2. Every post-freeze skill carries frontmatter distinguishing it from extracted material: `provenance: post-freeze`, an authorship date, and the ADR or engine sections it was derived from. A reader must never mistake reconstructed methodology for the founding architect's own words — the engines remain the authority; a skill that contradicts its source engine is a bug in the skill (per the library's own rule).
3. **Authoring order follows phase need, not index order:** file 10 (AI Orchestration — kernel instructions, job authoring, kernel swap) before Phase 2; file 07 (Security & Privacy) and file 05 (Testing & Verification) before Phase 2's MCP work; the remainder as their phases arrive. Each file is derived from its corresponding engine document(s) plus the ratified ADRs — synthesis, not invention.
4. The frozen library's conventions bind the new files: the nine-field template, stable S-### IDs, one category per file, append-only growth.

**Consequences.** The corpus's internal citations become resolvable, and the skills — the mechanism by which judgment survives model replacement (FABLE §15) — actually exist for the models that need them. Cost: 103 skills is real authoring work spread across phases, and reconstructed skills are one step removed from the source; the provenance marking keeps that honest. Deliberately *not* decided here: skill content — each file lands via normal review, not this ADR.

**Alternatives considered.** (1) *Leave the gaps; treat the engines as sufficient* — rejected: engines are philosophy at reading length; skills are procedures at execution length; the corpus itself declares both necessary, and dangling IDs corrode trust in every other reference. (2) *New skill IDs in a new location, deprecating S-013+* — rejected: breaks every existing citation in frozen documents that can never be updated to the new IDs. (3) *Author all 103 up front* — rejected: most skills serve phases months away; authoring against unbuilt systems produces speculation, not procedure (and violates the roadmap's one-phase-at-a-time discipline).

**Future review criteria.** Reopen if: (a) a post-freeze skill is found contradicting its source engine — fix the skill, and audit its siblings from the same authoring session; (b) the kernel's native skill format diverges from the library's template — the library stays kernel-neutral and gets *rendered* into kernel dialects (ADR-003), never rewritten in one; (c) by Phase 7, any phase-critical skill remains unwritten — that is a roadmap gate failure, not a backlog item.

# ADR-035 — The Runtime Conversation Loop and the identity guarantee
**2026-07-13 · Accepted** — operator directive 2026-07-13 (results: heard/replied/overlay/sanitizer PASS; barge-in FAIL, ambient FAIL, conversation quality FAIL; identity leak "I'm Qwen3"). Supersedes ADR-034 items 3's *mechanism* (its barge-in wiring caused self-interruption); everything else in ADR-034 stands. Objective, verbatim: a conversational Runtime that genuinely feels like Iron Man's JARVIS.

**Context — root causes, from code and observed behavior.**
1. **Self-interruption / "always listening":** ADR-034 wired `on_recording_start → interrupt` while the mic stayed live during playback. With `ambient_mode: true` (operator knob) the VAD heard **JARVIS's own speech from the speakers**, cut playback after the first sentence, transcribed JARVIS's own words as an operator turn, and looped — exactly "speaks only the beginning", "interrupted continuously", "repeatedly enters transcription", and the overlay/voice desync (the overlay renders the full turn; speech died early).
2. **Identity leak:** the compact persona (derived from the Kernel Constitution's Identity section for the small local models) never explicitly forbade naming the underlying model, and nothing downstream enforced it.
3. **No conversational memory:** the voice adapter sent each utterance as a bare single message — follow-ups had no context. Contextless replies read as "not conversational."
4. Verified component facts (RealtimeSTT 1.0.2 source, `core/recording.py`): `listen_start` resets **per listening cycle**, so `wake_word_activation_delay` is a per-turn wake-free VAD window; `on_wakeword_timeout` fires exactly once when that window closes; `set_microphone(False)` stops all audio feeding (no VAD, no wake processing, no transcription); `wakeup()`/`abort()` exist for manual control.

**Decision.**

1. **Explicit conversation states**, owned by the voice adapter and published through the ADR-034 state file:
   `PASSIVE` (wake-armed) → `WAKE` (`on_wakeword_detected`) → `LISTENING` (VAD/recording) → `THINKING` (interface call) → `SPEAKING` (TTS) → `AMBIENT WINDOW` (wake-free listening, `conversation_window_s`) → back to `LISTENING` on speech or `PASSIVE` on `on_wakeword_timeout`. No overlapping states.
2. **The microphone is muted to the recorder for the whole of THINKING + SPEAKING** (`set_microphone(False)` on reply entry, restored on exit, `post_speech_pause_s` breath before the window opens). Transcription can never run while JARVIS speaks; JARVIS cannot hear himself; keyboard/room noise cannot start a recording mid-reply.
3. **Barge-in is wake-word-only and runs on its own detector** (`jarvis_bargein.py`: a dedicated 16 kHz input stream feeding an openWakeWord model, active **only** while a reply is in flight). "Hey Jarvis" always cuts JARVIS off — his own voice, typing, and room noise structurally cannot (a wake model, not a VAD). The three signals are now distinct and never concurrent: wake-word detection (PASSIVE, in the recorder), interruption detection (THINKING/SPEAKING, in the barge-in listener), transcription (LISTENING/WINDOW, in the recorder).
4. **Ambient Mode is redefined as the conversation window, not permanent transcription:** after each reply, `wake_word_activation_delay = conversation_window_s` (~12 s) of natural wake-free turn-taking; silence beyond it returns to PASSIVE (`on_wakeword_timeout` publishes the transition). The `ambient_mode` and `idle_timeout_s` knobs are retired; a permanent always-transcribing mode no longer exists.
5. **Voice keeps a rolling in-memory conversation history** (same `history_turns` pattern as the overlay; still no durable state) so follow-ups have context. Voice and overlay stay one interface via the state file: every indicator and every rendered word tracks the same state transitions the voice actually performs.
6. **Identity is a Runtime guarantee, enforced at the single interface** (Convention 5 chokepoint, so voice, overlay, and browser are all covered): `jarvis_identity.py` deterministically replaces model self-names (qwen-family, vendor names) with **JARVIS** and infrastructure names (Ollama, LiteLLM, Bifrost) with **"the Runtime"**, stream-safe across chunk boundaries (hold-back buffer). The Kernel Constitution's Identity section gains the explicit rule (operator-directed; journaled): if asked what you are or what model you run, the answer is JARVIS — never a model, vendor, or version. Prompt reduces the attempts; the scrub makes the guarantee. Diagnostics/developer visibility (Convention 4) remains the only sanctioned exception, and only where the operator explicitly enables it.

**Consequences.** The loop is deaf while speaking by construction, interruptible by intent only, conversational for a window after each turn, and silent about its organs on every surface. Costs: a second short-lived input stream during replies (shared-mode capture; validated on this hardware), interruption during a reply requires the wake word (deliberate, per the operator's own spec), and questions genuinely *about* Ollama-class software get their names scrubbed in normal mode — the diagnostics escape hatch exists for that.

**Alternatives considered.** (1) *Energy/VAD-threshold barge-in* — rejected: indistinguishable from the echo/noise class that caused this failure; (2) *echo cancellation (AEC) to keep the mic hot while speaking* — rejected: heavy new component for a problem muting solves outright (Law 10); (3) *identity scrub in each surface* — rejected: N seams to keep honest instead of the one interface; (4) *prompt-only identity fix* — rejected: probabilistic, and this is a guarantee (ADR-034 item 2's producer≠verifier logic).

**Future review criteria.** Reopen if: (a) the operator wants voice interruption without the wake word — that requires AEC or hardware echo isolation, a new component decision; (b) RealtimeSTT's successor changes `set_microphone`/window semantics — re-satisfy this loop before swapping (Law 4 gate); (c) a legitimate need to discuss the named tools arises in normal mode — extend Convention 4's visibility switch rather than weakening the scrub; (d) shared-mode double-capture fails on future audio hardware — fold interruption detection into the recorder's wake path with mic un-muted for wake-only (the fallback shape, at the cost of self-wake risk).

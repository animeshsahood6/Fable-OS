# ADR-013 — Trust tiers, egress allowlist, and memory quarantine are the injection-defense structure
**2026-07-10 · Accepted** — ratifies [ARCHITECTURE-V2](../ARCHITECTURE-V2.md) §3/§12; companion to ADR-009 and ADR-012.

**Context.** ADR-009 separates *who may act*; something must still govern *what content may trigger what*, and how untrusted content is prevented from persisting into trusted instruction ([C2](../reviews/2026-07-09-red-team-review.md)). Detection cannot do this (SECURITY_ENGINE §7.2); classification and structure can. OWASP's Top 10 for Agentic Applications (2026) independently lists memory poisoning and uncontrolled egress among the dominant real-world agentic failure classes.

**Decision.** Every piece of content the system handles carries a **trust tier**:

| Tier | Source | May trigger |
|---|---|---|
| T0 operator | direct human instruction, approved | anything |
| T1 system | this repo's own docs/config | read, plan |
| T2 authenticated | the operator's own files, authed services | read; writes to `data` **quarantined** |
| T3 open | web pages, inbound email bodies, internet tool output | read only, in the READER context; cannot invoke SEND/WRITE/PAY tools |

Three enforcement mechanisms, all configuration rather than exhortation:

1. **Memory quarantine.** Anything derived from T2/T3 is written to `data\memory\_quarantine\` with `reviewed: false` frontmatter. The recall index excludes unreviewed quarantine by default. Promotion to trusted memory requires operator approval or a T1 rule. A poisoned memory can never silently become a trusted instruction.
2. **Egress allowlist.** An L3.5 guard limits which hosts any capability may reach; exfiltration to an arbitrary attacker domain is blocked structurally, not entrusted to the model.
3. **Injection canary suite** runs at every model, kernel, or MCP-profile change (shared gate with ADR-009), and — per ADR-018 — after any MCP server or skill update.

**Consequences.** The injection persistence chain (C2) is broken at both ends: T3 content lands where it cannot act (ADR-009) and cannot persist into trust (quarantine). Cost: a quarantine review habit for the operator (batched into the morning brief), and an allowlist that will occasionally block a legitimate new host until edited — the failure mode is a visible denial, never a silent breach, which is the correct default for this operator.

**Alternatives considered.** (1) *Provenance metadata without enforcement* — rejected: metadata nobody checks is documentation, not defense. (2) *Full egress proxy with TLS inspection* — rejected: a resident service and certificate maintenance burden (Law 10) out of proportion to a single-machine system; a host allowlist at the capability layer captures most of the value. (3) *Trusting model-level guardrails* — rejected on the evidence cited in ADR-009.

**Future review criteria.** Reopen if: (a) quarantine review load exceeds what the morning brief absorbs — the promotion rules need tiering, not abandonment; (b) a canary ever fails in production use — incident; (c) the OS or kernel ships native content-provenance/taint tracking that can fill this role's contract — adopt and thin the custom layer; (d) a new content channel appears (e.g. voice per ADR-022) — it must be assigned a tier here before it ships.

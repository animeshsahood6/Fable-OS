# ADR-017 — Gateway hardening and succession: LiteLLM retained under mandatory controls; Bifrost named successor
**2026-07-10 · Accepted** — from the [2026-07-10 architecture review](../reviews/2026-07-10-architecture-review.md) §3.1 A3 / §6 R1; extends ADR-002 and amends the gateway row of COMPONENTS.md.

**Context.** LiteLLM remains the best fit for the gateway role (100+ providers, one YAML, OpenAI-compatible localhost endpoint), but its 2026 security record changed its risk class: a suspected PyPI supply-chain compromise (March 2026, malicious payloads in released proxy code), a pre-auth SQL injection in API-key verification (CVE-2026-42208, fixed v1.83.7), and an auth bypass via Host-header injection (CVE-2026-49468, June 2026). "It only listens on localhost" is not a full answer — browser-based SSRF and DNS-rebinding reach localhost, and the Host-header CVE is exactly that class. The gateway holds every API key the system owns.

**Decision.** LiteLLM is retained **only under all of the following controls**, which are part of the role's contract, not suggestions:

1. **Version pinned** to a vetted stable release (≥ v1.83.10 at time of writing), recorded in VERSIONS.md; upgrades are deliberate quarterly-checkup acts, never automatic.
2. **Package integrity verified** at install time (hash verification against the pinned version) — non-negotiable after a supply-chain incident.
3. **Master key enabled**; all consumers authenticate.
4. **Bound to 127.0.0.1** explicitly; verified by the watchdog, not assumed from defaults.
5. **Security advisories checked** as a standing quarterly-checkup item (GitHub advisories for the pinned package), with out-of-cycle patching when a pre-auth issue lands.

**Succession (Law 4):** the named successor is **Bifrost** (Go, OpenAI-compatible, materially smaller attack surface), replacing OpenRouter in the registry (OpenRouter is cloud, and fails Law 6). The floor remains the ~50-line own proxy of ADR-002. Swap cost stays low by contract: every consumer knows only `localhost:4000/v1`.

**Consequences.** The single most credential-rich component gets defense proportional to what it holds, at the cost of pinning discipline and slower upgrades. Nothing else in the system changes — that is the seam doing its job.

**Alternatives considered.** (1) *Replace LiteLLM with Bifrost now* — rejected: LiteLLM's breadth and YAML routing are still the best operator experience, its team responded to 2026 with real hardening, and swapping the gateway during Phase 1 adds risk to the least mature moment; the successor is named, contract-checked, and rehearsable instead. (2) *No proxy at all (Ollama's native `/v1` endpoint)* — rejected as the primary: it serves only local models, so multi-provider routing and fallback chains — the point of ADR-002 — disappear; retained as the degraded-mode answer if the gateway is ever down. (3) *Cloud gateway (OpenRouter)* — rejected: violates Law 6 and moves every key off-machine.

**Future review criteria.** Reopen if: (a) another critical pre-auth vulnerability or any supply-chain event lands — execute the Bifrost swap per MAINTENANCE.md §2 rather than absorbing a third strike; (b) Bifrost's health declines (quarterly pulse) — name a new successor before it is needed; (c) LiteLLM ships a security-support policy (LTS releases) — re-pin to that channel; (d) the gateway role's traffic ever includes non-chat modalities — that is ADR-022's seam, not this one's; do not widen this contract.
